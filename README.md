# 建築ドローイング制作支援（drawing-support）

Instagram @myo22myo22 の毎朝 7:00 投稿（有名建築のドローイング）の制作を支える、1人用のローカルWebアプリです。

- サーバー不要。`index.html` をブラウザで開くだけで動きます。
- データはブラウザの中（localStorage と IndexedDB）にだけ保存します。外部へは何も送信しません。
- 依存ライブラリなし・ビルド不要（素の HTML / CSS / JavaScript）。

## このアプリがしないこと

- **Instagram への投稿・予約はしません。** 投稿と予約は本人が Instagram で行い、アプリには「予約した」「アプリで確認した」を記録するだけです。
- **生成AIへ画像生成リクエストを送りません。** プロンプトを作ってコピーできる形で出すところまでです。生成は ChatGPT で行います。

## 起動方法

1. `apps/drawing-support/index.html` をダブルクリックして、ブラウザ（Edge か Chrome を推奨）で開く。
2. 初回は、使用済みの背景色10件と題材サンプル「プレミアホテル門司港」（背景 白群 × 月 白 でマスター決定済み）が入った状態で始まります。

ブックマークしておくと次回からすぐ開けます。

### うまく開けないとき（予備の方法）

このフォルダで次を実行し、表示された `http://localhost:8765/` を開きます。

```bash
python -m http.server 8765
```

> ダブルクリックで開いた場合（`file://`）と `localhost` で開いた場合では、ブラウザ内の保存場所が別になります。どちらか一方に決めて使ってください。

## 使い方（制作フローの順）

画面上部のメニューで切り替えます。右上にはいつも、次の 7:00 までの残り時間が出ています。

- 進み具合は **月の満ち欠け** で表します：新月（下書き）→ 三日月（生成済み）→ 上弦（マスター決定）→ 十三夜（予約済み）→ 満月（アプリで確認済み）。
- 右上の「昼にする／夜にする」で、濃紺のテーマと紙色のテーマを切り替えられます（グリッドやInstagram風プレビューの地色も、ダークモード／ライトモードに合わせて変わります）。
- 制作画面では、選んだ色を当てはめた **ポスターの下絵** が常に横に出ます。「次の一手」ボタンが、次にやることへ案内します。

### 1. 題材を登録する（「制作」または「写真ストック」）

- 「制作」→「＋ 新しい題材」で、建物名／設計者／竣工年／場所／建物自体の色（主色・副色）／参考写真／投稿枠（日付、時刻は 7:00 固定）を入力します。
- 「写真ストック」に参考写真をまとめてドロップすると、1枚につき1つ「未着手」の題材として登録されます。「次の空き枠へ」で投稿枠に入れられます。
- ステータスは **未着手 → 生成中 → マスター決定 → 予約済み → 投稿済み**。操作に応じて自動で進み、手動でも直せます。

### 2. 色を決める（制作 → 色と組み合わせ）

- 背景色3候補・月の色2候補を和色リストから選ぶと、**A / A2 / B / B2 / C / C2** の表ができます。
- 色を選ぶ画面で「済」が付いている色は、背景に使用済みの色です。色にマウスを乗せると、その色を当てはめた下絵がその場で見られます。
- 参考写真があれば、下の「色サンプリング」に主要色と、背景3色 × 月2色の叩き台が出ます。写真をクリックして建物の色を拾い、主色・副色に設定することもできます。
- 各パターンは **未生成 / 済 / ★マスター** の状態を持ちます。

### 3. プロンプトをコピーする（プロンプト）

- 共通プロンプトの差し替え3か所（建物の説明文・月の色・背景色）を自動で埋めます。
- パターンごとの個別プロンプト（最大6本）と、全パターンを一括で頼む統合プロンプト1本を、ボタンでコピーできます。
- ChatGPT に参考写真を添付して貼り付けてください。

### 4. 候補を比べてマスターを決める（候補とマスター）

- 生成された画像を各パターンの枠にドロップします。「まとめて読み込む」なら、ファイル名の `candidate_A2_…` などからパターンを判定して振り分けます。
- 背景色ごとに3列、月の色ごとに2段で並びます。画像をクリックすると拡大します。
- 1つを「★ これをマスターにする」で決定します。決まった瞬間、その和色で画面いっぱいに表示されます。
- ファイル名の提案：候補 `candidate_<ID>_<背景色ローマ字>_<月色ローマ字>.png`、マスター `master_<題材>.png`。「この名前で保存」で、その名前を付けて保存し直せます。

### 5. キャプションを作る（キャプション）

- マスターの色名（日英）を使って自動生成します。英語が先、日本語が後、色の行は日英両方です。
- 「AI生成が完成形の作品」にチェックが入っていると、開示の一文（日英）が入ります。
- タグは 固定タグ（英語）＋題材別タグ＋日本語タグ（#ドローイング #建築）。
- 「キャプションをコピー」でワンクリックコピー。直接書き換えることもできます。右側に、Instagramの投稿風のプレビューが出ます。

### 6. データカードを作る（データカード）

- 設計者・竣工年・場所と、ポイント3つから、カルーセル2枚目用の画像（1080×1350、4:5）を作って PNG でダウンロードできます。

### 7. グリッドで色の並びを確かめる（「グリッド」）

- マスターが決まった投稿を Instagram の3列グリッドで並べます（左上が最新）。画像がない投稿は、背景色と月の色の模式タイルになります。
- 「候補を仮置きする」で、まだ決めていない題材のパターンを入れて、色の並びを確かめられます。
- 色が近い組み合わせ（連続する投稿、および常に縦に並ぶ3つ違いの投稿）を赤枠で知らせます。

### 8. 予約と確認（「次の一枚」）

- いちばん上に次の 7:00 の一枚が、その和色で大きく出ます。下には「これからの14日」が並び、空いている日を押すと題材を入れられます。
- 7:00 の枠ごとに **下書き → 生成済み → マスター決定 → 予約済み → アプリで確認済み** の進み具合が、月の満ち欠けで並びます。
- Instagram で予約したら「Instagramで予約した」を押し、**Instagramアプリの「予約済みコンテンツ」を目で見て確かめてから**「「予約済みコンテンツ」で確認した」を押します。
- 「アプリで確認済み」になっていない枠は、画面上部と各行に警告が出ます。投稿前日になると、確認済みでも再確認を促します。

## そのほかの画面

- **和色**：和色リスト（色名＋HEX）と、背景に使用済みの色の一覧（投稿順）。色の追加や、HEXの上書きができます。
- **設定**：共通プロンプトの文面、固定タグ、開示の一文、アカウント名の編集。バックアップの書き出し・読み込み、サンプルデータへのリセット。

## 携帯で使う

GitHub Pages に置いたURLを携帯のブラウザで開くと、そのまま使えます。メニューは画面の下に並びます。

- 公開URL：https://oie7oie26oie-lang.github.io/drawing-support/
- リポジトリ：https://github.com/oie7oie26oie-lang/drawing-support

### ホーム画面に追加する（おすすめ）

アプリのように全画面で開け、電波がなくても起動できます。iPhone では、ホーム画面に追加しておかないと、しばらく使わなかったときにブラウザがデータを消すことがあります。

- **iPhone（Safari）**：共有ボタン →「ホーム画面に追加」
- **Android（Chrome）**：右上のメニュー →「ホーム画面に追加」または「アプリをインストール」

### PC のデータを携帯へ移す

データは端末ごとに別々です。自動では同期しません（外部には何も送らないため）。

1. PC で「設定」→「書き出す（画像を含む）」を押し、できた JSON ファイルを携帯へ送る（AirDrop、クラウドのフォルダ、自分宛てのメールなど）。
2. 携帯で「設定」→「バックアップから読み込む」で、そのファイルを選ぶ。

> 読み込むと、その端末のデータは**丸ごと置き換わります**。PC と携帯の両方で別々に編集した内容を混ぜることはできません。「PC で制作 → 携帯に移して予約・確認」のように、流れを一方向に決めておくと安全です。

### 携帯での操作の違い

- 色選び：色を押すと下絵に当てはまり、「この色にする」で決まります。
- 画像やバックアップの保存：共有シートが開くので、「画像を保存」や「ファイルに保存」を選びます。
- 候補画像・参考写真：枠を押して写真ライブラリから選びます。

### 公開についての注意

- URL を知っている人は、アプリ本体（画面、共通プロンプトの初期文面、初期サンプルの色と建物名）を見られます。
- 入力した題材・画像・キャプションは、それぞれの端末のブラウザの中にだけあり、公開されません。

### アプリを更新したとき

ファイルを直して GitHub に反映すると、次に開いたときに新しい版になります（つながらないときは、端末に残っている版で開きます）。

## データとバックアップ

- 題材や設定は localStorage、画像（参考写真・候補・マスター）は IndexedDB に入ります。
- ブラウザの閲覧データを消すと失われます。「設定」→「バックアップ」で JSON ファイルに書き出しておけます（画像を含めることもできます）。
- 別のブラウザやPCへ移すときも、書き出したファイルを「バックアップから読み込む」で戻せます。

## 初期データについての注意

- 和色の HEX は一般に流通している代表値です。出典によって少し差があるので、手元の基準と違う場合は「和色」画面で上書きしてください。
- サンプル「プレミアホテル門司港」の建物の色・ポイント3つ・投稿枠（初回起動日の翌日）は、動作確認用の仮の値です。
- 使用済み10件のうち、門司港以外の9件は色名と建物名だけの「投稿済み」として入っています（設計者などは空欄、投稿枠の日付なし）。
- 「マルクトハルは実測ティール、キャプション表記は浅葱色」は、投稿順が分からないため題材としては登録せず、「和色」画面のメモ欄に入れています。

## ファイル構成

```
apps/drawing-support/
├── index.html          入口
├── css/style.css       見た目（夜・昼の2テーマ）
├── js/
│   ├── colors.js       和色リストと色の計算（色差など）
│   ├── store.js        保存（localStorage / IndexedDB）、初期データ、バックアップ
│   ├── logic.js        組み合わせ表、プロンプト、キャプション、ファイル名、投稿枠の判定
│   ├── sampling.js     参考写真からの色抽出と叩き台の提案
│   ├── datacard.js     データカードの描画
│   ├── ui.js           画面共通（描画、イベント、ポスターの下絵、月相、色ピッカー、演出）
│   ├── view-subject.js 制作画面（6つの工程）
│   └── view-main.js    次の一枚（投稿キュー）／グリッド／写真ストック／和色／設定
└── README.md
```

共通プロンプトの初期値は `js/store.js` の `DS.DEFAULT_PROMPT`、和色の追加は `js/colors.js` の一覧に1行足すだけです。
